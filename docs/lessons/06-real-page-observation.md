# 第六课：真实页面观察与字段诊断

## 这一步做了什么

在用户日常 Chrome 的杭州银行「新增简历」页上，扩展实际读取了主文档的表单结构。用户点「扫描当前网页」后，可以展开基本信息、教育经历、实习、家庭、证书、奖惩等分组，看字段类型、必填与禁用状态。学校被识别为自动补全，教育类型、学历和学位被识别为自定义下拉，四个地区字段被识别为级联选择。

扫描只读取结构，输出不包含字段值。普通非敏感字段最多提供「已有内容」这一布尔信息；姓名、证件、联系方式、身体信息、声明答案、凭据及签名等字段连值的存在状态也不读取。诊断存放在扩展的会话存储中，与所选标签页和网址对应，扫描不会调用模型 API。

## 在 Agent 系统中的位置

闭环的第一步是观察。模型只有在获得实际页面结构后，才能把「毕业院校」与资料库路径对应，并判断是否需要添加经历。过去的观察器固定依赖演示页的四个字段；新扫描器开始把真实页面的 DOM 转为结构化数据。这是感知层的进展，执行层接入和真实填写验收还没有完成。

观察包含字段所在的分组和记录序号，而不只是平面的输入框列表。杭州银行每个经历模块中有 `form.el-form`，模块标题与「继续添加」按钮位于外层容器。它们的这些关系来自实际 DevTools 检查。若只按最近的 form 分组，就容易把添加按钮丢到页面其他控件中。扫描器保留外层经历分组，再用内部 form 统计记录。

## 用到的技术

**DOM 与可访问性语义。** DOM 是浏览器中的元素树。`label`、`aria-label` 和 `aria-labelledby` 提供控件名称；祖先元素提供分组关系；`required`、`disabled` 和 `readonly` 描述状态。框架的自定义下拉常把内部文本框设为 readonly，但整个选择器仍可通过选项交互。因此诊断保留输入框的原始状态，界面显示「通过选项选择」。实际值写入需要未来的选择工具。

**隔离执行环境。** `chrome.scripting.executeScript` 的 `ISOLATED` 环境让扫描代码使用扩展自己的 JavaScript 环境，读取同一份页面 DOM。它不调用页面的 Vue 实例、事件处理器或内部状态。脚本执行前后还核对所选标签页的网址，避免导航后把另一张页面当成原表单。[Chrome scripting 官方文档](https://developer.chrome.com/docs/extensions/reference/api/scripting)。

**数据最小化。** 诊断使用 `field-N`、`group-N` 等本次观察的临时编号，避免导出 DOM ID、完整 HTML 或请求内容。标签文字也有长度上限。健康和法律声明的单选答案、文本值及签名不读取。临时编号目前只用于诊断；未来执行必须增加快照版本和重新定位校验，不能拿旧编号直接操作变化后的页面。

**浏览器测试与 DOM 测试。** 实际 Chrome 扫描验证了真实页面上的字段分组与控件类型。jsdom 测试使用虚构的同类布局，检查组合框不重复计数、添加按钮属于正确分组、扫描不改变 DOM、敏感值 getter 不会被读取，并检查所有字段值均不进入报告。jsdom 没有真实布局，测试中的渲染矩形是显式替身，因此它不能代替实际浏览器验收。[jsdom 项目说明](https://github.com/jsdom/jsdom)。

## 已知不足与下一步

当前扫描覆盖主文档中已渲染的控件，未扫描 iframe 内部、Shadow DOM 内部和隐藏字段。杭州银行的六个声明补充文本框与签名画布没有独立可用标签，诊断列出七个待核实字段；它们不会自动获得填写权限。照片上传控件也是后续能力，隐藏的上传 input 尚未计入可见字段。

下一步把教育经历的观察送入决策层，生成可查看的字段映射与动作计划；随后接入自定义下拉、日期与自动补全的受限工具，并在动作后检查网页实际选中状态。学校查询和地区联动的网络请求用途必须根据实测核实，已有的运行期全面阻断不能直接套用到完整招聘表单。提交、投递、报名及电子签名确认均不属于自动工具。
