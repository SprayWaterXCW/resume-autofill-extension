# 第十六课：跨模板语义规划

## 这一步解决什么

项目需要把同一资料库填写到不同公司的招聘页面。变化可能是字段换了叫法，也可能是页面把逐条经历换成一个完整情况文字框。本轮把这两种变化纳入规划契约。

日志中的实际失败是五条获奖名称都被模型重复分配，随后局部修复删除十个目标。旧日志没有字段语义，不能还原它们各自用途。新版一方面减少这种错误，另一方面记录角色与来源，方便发现下一类问题。

## 在整体中的位置

资料编辑 → 结构化事实库 → 页面观察 → 模型提出语义映射 → 程序复验 → 控件执行 → 回读与结束复核。

本轮主要修改事实库、模型映射契约和复验三个环节。普通 Chrome 的工具栏入口、页面控件操作和后置条件检查继续承接已通过的计划。

## 1. 结构化语义角色

一次映射现在可以包含：

```json
{
  "fieldId": "field-3",
  "sourcePath": "awards.0.description",
  "semanticRole": "description"
}
```

semanticRole 是有限枚举：

| 角色 | 含义 | 本地资料来源 |
| --- | --- | --- |
| name | 名称 | 同条 name |
| description | 独立描述或详情 | 同条 description |
| scope | 国家级、省级等范围 | 同条 scope |
| rank | 一等奖、金奖等次 | 同条 rank |
| level | 尚需实际选项确定含义的等级 | 同条 level 投影 |
| summary | 完整记录或全部情况 | 本地 summary 投影 |

模型负责解释“荣誉事项”“成果叙事”等陌生表达。Zod 验证角色来自枚举、路径和目标来自当前目录。本地校验继续检查明确标签是否与角色冲突，并确认来源属性和记录序号。例如模型把描述声明为 name，无法通过明确描述标签的独立校验。

角色本身是模型提议，不构成页面事实。陌生标签的含义仍可能判断错误，后续回读也只能证明写入值保留，不能独立证明语义解释正确。跨模板评测需要单独设置预期映射。

## 2. 把正确名称与错误重复目标区分开

同一张卡片有明确名称字段时，它可以使用 name；旁边一个用途未知的字段不能再使用同条 name。

校验先产生具体的语义冲突，局部修复仅排除冲突目标。若两个字段都明确表示名称，程序无法证明该保留哪一个，就继续报告冲突。这样能保留有独立依据的填写，避免用遍历顺序决定语义。

## 3. 确定性的汇总投影

用户仍在资料页维护名称、级别、等次、详细信息四个属性。网页需要整段文字时，本地把已有属性格式化成：

```text
名称：虚构奖项
级别：国家级
等次：一等奖
详细信息：虚构成果说明
```

这段内容没有模型生成的事实。缺失属性不补全；已有属性处于未确认或冲突状态时，不生成会隐去该问题的完整汇总。

来源链分两层：

1. awards.0.summary 的 derivedFrom 指向 awards.0 的已确认属性。
2. formAnswers.awardsSummary 的 derivedFrom 指向每条 awards.i.summary。

模型只知道投影的用途与路径。真正的组合文本仍由本地 getValue 取得，不进入模型上下文或日志。这沿用事实库的值与元数据分离。

## 4. 根据观察选择页面布局

只有文字框和逐条卡片所需的动作不同。观察上下文现在包含 hasAddCandidate，表示该区块是否观察到添加候选。这个标志不允许模型点击按钮，实际添加仍由现有工具核验。

全量汇总只适用于未截断观察中的单字段、单条目文字区块，而且没有添加候选。若有多个字段或添加候选，继续按记录计算卡片需求，不能把全部记录塞到第一张卡片。

仅有获奖区块时使用获奖加竞赛的全量来源；两类区块都存在时分别使用本类汇总。程序复验路由，避免模型只填第一条或漏掉另一类记录。

这些条件基于当前观察。隐藏或未被识别的添加按钮仍可能影响判断，需要由更完整的观察和后续日志定位。

## 5. 工具契约与运行时校验

函数调用的 JSON Schema 为每个字段列出角色及允许的来源引用，缩小模型可提出的映射范围。模型返回后，运行时再检查语义、来源状态、区块、记录顺序、页面绑定及现有内容。

这种组合有两个作用：契约减少错误提议；运行时负责拒绝越界提议。模型接口支持结构化输出也不能保证语义永远正确。

## 6. 如何验证这一层

本轮有两种独立证据：

- 虚构 DOM 用例运行同一个页面执行器，检查真实写入、下拉选中、新增次数、已有内容保护和最终回读。
- 配置好的模型接收虚构页面元数据，独立预期判断路径、角色和分区是否正确。

前者证明程序行为与局部恢复符合契约，后者证明这次模型能够理解多个模板。137 项回归与 6 个模型案例通过，不等于已测过所有招聘网站。

获奖诊断保存字段类型、已观察角色、模型角色、计划来源和剔除结果，不保存标签原文或资料值。下一次失败可以先区分语义映射、资料缺失、卡片路由和控件执行问题，再修改对应环节。
