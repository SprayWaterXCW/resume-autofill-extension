# 第十三课：用户资料编辑与 Agent 事实库

## 这一步解决什么问题

用户需要点击插件按钮，打开网页，在输入框中维护简历。此前导入 JSON 的方式适合迁移，却不适合日常补充身高、体重、家庭成员或新经历。

本次在独立 Agent 目录中实现网页资料编辑器，复用已复制的简历 schema 和旧插件的“按 schema 生成字段、按列表添加经历”的流程。旧插件源码保持独立维护。

## 它在整个 Agent 中的位置

编辑器是事实来源的入口，保存动作代表用户确认资料。浏览器 Agent 再从事实库中取得可用的资料路径，模型根据网页标签关联路径，执行工具在本地解析实际值并填写。

```mermaid
flowchart LR
  A[用户编辑网页表单] --> B[Schema 规范化]
  B --> C[检查版本并保存扩展本地资料]
  C --> D[建立用户确认的事实库]
  D --> E[公开字段标签与资料路径]
  E --> F[模型提出字段映射]
  F --> G[受控执行工具]
  D -->|本地读取实际值| G
  G --> H[招聘表单与回读核验]
```

同一份 schema 约束导入、编辑、保存和目录生成。这样页面中的“身高”不会生成一个执行器不认识的新名字，多条经历也能保持稳定索引。用户资料内容不进入模型请求和执行记录。

## 技术一：Manifest V3 中的独立扩展页面

编辑器是扩展自身的 HTML 页面，地址以 chrome-extension 开头。工具栏面板使用 chrome.runtime.getURL 获取地址，并用 chrome.tabs.create 打开普通 Chrome 标签页；options_ui 同时提供“扩展程序选项”入口。

编辑页与后台共享扩展本地存储，打开和保存不依赖 4174 服务或模型 API。模型服务继续负责 Agent 的规划。Chrome 权限、扩展公钥和 ID 均未变化。

相关文件：

- agent-extension/profile-editor.html、profile-editor.css：页面与布局。
- agent-extension/src/profile-editor.js：表单状态、分组导航、列表编辑、保存和备份。
- agent-extension/src/profile-editor-entry.js：初始化。
- scripts/build-extension.js：构建浏览器脚本。

## 技术二：Schema 驱动的表单

每个资料区块定义 key、中文标签、字段及输入类型。group 生成一组输入框；list 生成多张记录卡片，并提供添加、删除或清空按钮。

所有字段都有对应的 label 和输入框 ID。渲染使用 DOM 节点和 textContent，不把导入值拼成 HTML。切换分类只改变显示，不丢弃其他分类的输入；增加和删除记录前先收集所有分类的修改。

日期使用带示例的文本输入框。HTML 原生 date 控件要求年月日，可能丢掉旧资料中只有年月的经历日期。保存继续使用既有规范化函数，填写网站所需的日期精度由已确认的日期补全规则处理。

保存同时覆盖所有分类。页面显示未保存状态，离开时使用 beforeunload 提醒。备份导入先显示在表单中，用户核对并保存后才更新事实库。

## 技术三：版本检查与串行保存

多个编辑页、工具栏导入和 Agent 执行共享一份资料。单纯 storage.set 会让后保存的旧页面覆盖新资料。

后台为每次资料写入生成 revision。编辑器加载时记住 baseRevision，保存时检查它与当前存储版本相同，再写入新版本。旧资料没有 revision 时使用已有导入时间构造兼容版本，首次保存后进入新版本机制。

检查和写入在同一后台队列中串行执行。否则两个请求可能都先读到旧版本，然后同时通过检查。一个请求成功后，另一请求会收到冲突提示，保留表单修改，允许先导出备份再核对。

保存排队期间不能启动新的扫描、规划或执行；已有 Agent 任务运行时不能更换资料，避免任务中途切换事实来源。成功保存也会使此前只读计划失效，下一轮重新规划。

## 技术四：扩展内部消息与私人值边界

工具栏的 profile-status 只返回数量与区块摘要。新编辑页需要真正的字段值，因此增加 profile-editor-load 和 profile-editor-save。

后台验证消息发送方的扩展 ID 和编辑页 URL。招聘网站中的内容脚本不能通过这些消息读取整份私人简历。Chrome 本地存储的访问级别仍是 TRUSTED_CONTEXTS。

编辑保存继续经过同一资料导入规范化与事实库构建过程，丢弃未知属性、原始文本和 API 设置。虚构评测资料的标记在编辑和备份过程中保留，防止评测资料被当作真实简历用于招聘网站。

## 如何验证

自动测试使用虚构资料，验证：

1. 修改身高、体重和家庭成员后，所有未修改的原始资料保持一致。
2. 保存并重新打开后，电话号码、年月精度、家庭成员与获奖记录仍存在。
3. 新用户不用模型服务即可建立资料；添加和删除经历不会丢失其他分类的未保存内容。
4. 两页同时编辑及两个并发保存请求只能有一个版本成功写入。
5. Agent 忙碌、无效备份与过期版本不能改变已保存资料。
6. 备份导入先保留在表单中，导出可重新导入，未保存时离开会提示。
7. 整份私人资料的消息接口拒绝招聘页发送方。

全部 114 项测试通过。普通 Chrome 中另行检查扩展更新到 0.7.0、工具栏打开编辑页、原有资料自动载入，以及教育和家庭成员表单。真实资料未被本次测试修改；浏览器检查不等于真实招聘页的控件修复验收。
