# 第二十六课：从真实遗漏改进观察、控件执行与资料库

## 这一步在整个 Agent 中的位置

本轮沿着「观察 → 规划 → 校验 → 执行 → 回读 → 重新观察」检查两个真实招聘表单。重点是把遗漏追溯到具体环节。表面上都是一个空框，原因可能是网页尚未加载、日期被读错、资料缺少独立属性、模型借用了不同含义的资料，或控件内部选择尚未确认。

本轮没有将某一家公司的字段编号写进映射表。改动覆盖通用的日期身份、语义边界、金额区间，以及观察到的 Phoenix 组件协议。组件协议能复用到采用相同控件结构的网站，但并不保证所有招聘平台的控件都受支持。

## 1. 观察不能只看 placeholder

真实日历输入框的 placeholder 可以是「年」，但点开后要求选择完整年月或日期。过去的扫描器据此把完整控件当成一个独立年份输入，模型只能在错误的候选来源中选择。

现在先看原生 input 类型、控件容器和字段标签，识别完整日历；只有明确分开的年、月、日才设置 `datePart`。完整日期控件不接受 `startDateYear` 之类的单位投影。获奖时间也有独立的 `date` 语义角色，不能接收奖项级别。

这是观察表示的修复。LLM 再强，也无法从一个被错误编码为年份框的工具参数中可靠地选择完整日期。

## 2. 为什么选中选项还不算成功

民族和地区选择器有两种状态：弹层里的暂存选择，以及主表单里的已确认值。日志曾显示 `rowSelected=true`、`pathMatched=true`，但 `panelClosed=false`、`valueMatched=false`。这说明暂存选项已选中，确认动作没有提交控件内部状态。

该组件的确认事件挂在按钮内容节点上。执行器现在在已验证的局部弹层页脚中点击内容节点；事件也会向外层冒泡。它不搜索整页的任意「确定」按钮。选项点击后还会重新取得当前行，避免 React 替换节点后继续检查已经脱离文档的旧行。

核验必须同时检查：目标身份保持、选择路径匹配、主字段显示正确、弹层关闭、稍后的整页回读保持。任何一层没有通过都不能计为成功。

## 3. 缺少资料与模型错配

第二志愿不等于第一志愿；可面试城市不等于工作地点；生源地不等于籍贯；推荐人不等于紧急联系人。学历层次与学习形式也应来自不同属性。论文的标题、日期、期刊和作者顺序不能从一段笼统的发表情况中任意拆出。

这些边界在规划候选、完整计划验证和浏览器写入前都检查。模型仍负责理解同义标签，但不能跨越已知的概念差异。自定义问答先采用题目原文规范化匹配：统一字符宽度、空白和标点，不把「听说过」与「参加过」当成同一个问题。

资料编辑页加入独立的题目和答案、论文记录、专业类别、生源地、推荐人、面试城市等。用户确认过的答案才成为可执行事实。新增空输入框不会自动生成「否」「无」或一个推测的获奖日期。

## 4. 投影与薪资区间

资料原文保持在本地。日期单位、地区层级组合和明确周期的金额换算是带 `derivedFrom` 的投影，保留来源路径。金额没有注明月薪或年薪时，不能依据单位猜测周期。

独立的期望月薪可以是金额或区间，并优先于年薪换算。网页选项经过 Unicode NFKC 规范化，再解析单位和上下界。用户明确填写的区间只匹配同一范围；一个金额可以匹配唯一包含它的范围。若边界同时落在两个区间中，则存在歧义，留待核对。执行器不擅自选择一个看起来更接近的区间。

获奖范围采用类似的包含关系：网页的「院校级」可以接收明确的「校级」或「院级」，精确选项优先。同一含义对应多个可见选项时仍拒绝猜选；不会把级别推断成一等奖。

## 5. 局部重试预算

添加新经历后需要重新规划，但不应重新无限尝试同一个坏控件。过去单个民族或地区选择器的失败，会随每次新增卡片重试，耗尽整页写入预算。

现在按唯一的逻辑字段身份和来源路径记录尝试次数。相同目标最多两次；到达上限后继续其他字段和记录。新出现的卡片仍有自己的预算。身份含糊时不凭编号相同复用状态。

这属于局部失败隔离。它不把失败变成成功，而是使一个不支持的控件不再阻止其他任务完成。日志保留之前的错误和后续恢复。

## 6. 刷新后立即开始

异步网页可能先展示骨架，再挂载表单。0 个字段不是「全部填完」。Agent 在原文档中有界等待可编辑字段或已识别的添加控件出现，期间不调用模型、不填写。等待中同样检查停止请求和文档身份；超时仍没有表单则明确返回 `FORM_NOT_READY`。

这是任务内的就绪检查。真实验收仍然只在刷新后点击正常开始按钮，不要求先执行扫描或手动等待。

## 7. 多轮规划要保留来源占用关系

Agent 会在添加卡片后重新观察和规划。为了控制上下文大小，模型只看还需要处理的目标。这带来一个容易忽视的问题：已填好的「就读学校」从待处理目标中消失了，但资料目录中的 `educations.0.school` 仍然存在。若下一轮没有保留关系，模型可能把这个来源再借给「研究方向」。

本轮真实复核发现了这种情况。网页回读与写入值一致，但研究方向中出现了学校或专业；其他语言能力中出现了英语成绩。它们是语义错误，不能因为 DOM 回读通过就算正确。

现在每轮完整页面上下文携带已核验字段的 `knownSourcePath`。候选生成先排除被其他记录字段占用的来源，完整计划校验再次检查。已填写目标可以继续核验自己的来源；同一普通信息在两个独立区块中确实重复提问时，仍允许按已识别含义复用。例如现居城市和相同的联系地址城市可以复用，教育记录的学校不能移用到课题描述。

这是跨步骤状态管理。它与步数、重试预算、文档身份共同构成 Agent 的工作状态；不需要把真实资料值放进模型上下文。来源占用也不代替语义检查：研究方向只接受独立的课题或研究属性，其他语言摘要只由资料库中明确命名的非英语语言记录生成。

已核验目标同时退出后续模型的待处理列表。否则，私密字段的 `hasValue` 因不读取值而为未知时，模型还可能反复为它换来源或标为歧义。这里依据的是本轮写入后的有效凭据，既有用户内容不会被取得为 Agent 成果。后续回读若发现丢失或改变，撤销凭据、移出来源占用，再依据新观察决定是否还能填写。

## 8. 写入权限与回读身份是两件事

另一真实页面在教育信息联动之后，将「学历」控件自动变为只读和禁用。它仍显示已填写的值，但之前的目标匹配把编辑权限变化看成字段已消失，撤回了成功计数。日志能确认这一点：同一字段的类型、分组、记录索引未变，`disabled/readOnly` 从假变为真，`hasValue` 为真。

新版本把这两项职责分开：完整计划和写入目标的结构检查仍严格比较编辑权限；已有写入凭据只在问题含义、记录索引、控件类型、日期单位等保持且身份唯一时，允许随「可编辑 → 锁定」转移。之后必须回读与原凭据中的值一致。这个转移只用于审计，不授予写入权限，不能用于把新值写入锁定字段。

虚构回归同时覆盖锁定后原值保持与锁定后被改值：前者最终回读通过，后者仍报不一致，并保留现有内容。民族也限制为明确的族别来源；旧的「民族/国籍」原始字段不直接参与民族选择，只有本地确认为族别的投影可以参与，避免模型选中混合来源后走错误的控件路径。

## 9. 日志、测试与真实验收各证明什么

本地日志新增封闭的阶段诊断，只接受预定义的布尔值、数量和时间。它记录是否选中、是否关闭、是否发生原生输入事件、写入和失焦之后是否保持；不记录选项文本、证件号或资料值。

虚构回归可以验证协议、语义约束、区间歧义、停止与文档绑定。它不能证明真实网站兼容。真实验收使用普通 Chrome、原有模型与资料，维护更新之外只点击开始；独立月薪内容来自用户本轮明确要求。各轮结果及尚未解决的问题见 [真实遗漏报告](../../reports/observed-omissions-2026-10-06.md)。

对已有内容，系统还检查是否像是已知资料的语义错配，但「内容相同」本身不能证明这个值由 Agent 写入。扩展重新加载后，上一轮网页内的写入凭据可能不再可用。本轮保留已有内容的检查因此只提示了三个字段，未自动清空；日志中的九个来源命中包含同一资料的派生路径，不能解释为九个错误字段。用户已授权刷新后，才按正常入口重新进行完整验收。

所以需要分别报告：写入回读是否保持、含义是否合适、尚有多少空白、资料缺少哪些属性、哪些已有值需要用户核对。「0 个执行失败」只回答其中一个问题。

## 本步涉及的技术如何配合

**事实约束（grounding）**：一个答案必须指向用户资料中的已确认事实。日期补全、地区组合、其他语言摘要和薪资换算都保留来源；不是让模型生成一个看起来合理的值。

**函数调用与运行时契约**：模型提出字段 ID 和资料路径。候选集合限定它能提出什么，完整校验再检查来源、记录顺序、角色和观察快照。执行器收到的是通过验证的动作，模型不能调用任意点击或提交功能。

**前置条件与后置条件**：写入前检查原文档、目标身份、现有内容和权限；写入后检查控件确认状态与回读。两组检查回答的问题不同，因此自动锁定可以改变写入权限而不必撤销一个仍可证明的回读结果。

**状态管理和重新规划**：经历卡片数、已核验来源、重试次数、文档身份和待补资料跨步骤保留。动态网页产生新节点或新卡片时，Agent 重新观察并规划，不能拿旧编号继续猜操作。

这些环节共同解决真实表单的问题。当前版本为 0.7.26；虚构回归、真实表单结论和仍留空的资料见本轮报告。两种验证的结果分别记录。
