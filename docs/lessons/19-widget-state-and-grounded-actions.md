# 第十九课：控件状态、动作副作用与可验证的执行

## 这一步在 Agent 中的位置

Agent 已经有观察、规划、受限工具、回读、重新规划和事件记录。本次修复集中在“计划中的一个字段，如何在真实动态网页里稳定地完成”的环节。

网页状态会随每次动作变化。LLM 正确匹配学校字段，只是产生了一个可执行的意图；执行器还需要确认控件、选择真实选项，并观察组件是否接受这次动作。

## 1. DOM 节点与任务对象

DOM 是网页的物理结构。用户看到的“一个日期”可能包含两个输入框、多个外壳、一个显示值节点和一个挂在页面末尾的菜单。

因此观察层要生成任务对象：区块、经历卡片、字段、日期端点和单位。它们由可观察标题、结构和控件协议推导。观察失败会把学校、公司、奖项混在同一张卡片里，影响后面的所有决策。

本次没有用某家公司的域名、生成 CSS 类名去确定字段用途，而是改进有界标题识别、相邻结构和通用选择器识别。以后遇到相似结构，可以复用这些判断。

## 2. 输入查询与已提交的值

一个可搜索的下拉框通常有三种状态：未选择、正在搜索、已经选择。

| 状态 | 查询输入 | 显示节点 | 菜单 |
| --- | --- | --- | --- |
| 未选择 | 空或提示文字 | 空 | 关闭 |
| 正在搜索 | 查询词 | 可能仍空 | 打开 |
| 已选择 | 可能重新变空 | 已提交选项 | 应关闭 |

所以，“输入框里有字”无法证明填写成功。我们必须找到菜单中的唯一匹配项，点击它，关闭菜单，再读取显示节点。候选项外壳和内容重复出现时，需要按包含关系去重；不同选项恰好同名时继续保持歧义。

这相当于为控件实现一个小型状态机。`open`、`search`、`commit` 是执行阶段，`VERIFIED`、`OPTION_UNAVAILABLE`、`OPTION_NOT_COMMITTED` 是观察到的结果。状态机可以测试，也可以记录具体失败位置。

## 3. 控件身份与稳定证据

计划需要绑定到实际节点。当前检查五项：节点仍连接、字段标签一致、控件类型一致、逻辑区块一致、经历根一致。

但有些属性本来就会变化。真实页面的年份选择器会清空 `placeholder`，用另外一个节点显示选择结果。如果每次都只从提示文字读取日期单位，选择之后就会误认为字段改名。

修复使用 `WeakMap` 保留同一选择器节点上实际观察到的日期单位。缓存中没有日期值。新的明确单位优先；选择器被替换时不能沿用旧证据；标题、区块、经历仍独立检查。

`WeakMap` 适合用 DOM 节点作为键，节点被回收后记录也可回收。它不是“忽略页面变化”：缓存的是先前已经观察到的稳定语义，用于抵抗组件的临时 UI 变化。负例测试必须证明它不会隐藏真实变化。

## 4. 动作的副作用与来源归属

选中年份可能让月份自动变成默认值。这是动作对其他控件产生的副作用。如果随后只判断“月份非空”，就会把网页生成的默认值当成用户填写。

本次执行器在动作前观察同一记录、同一端点和同一日期问题的相邻单位，只记录原本为空的控件。动作成功后，若这些控件出现值，程序在当前页面内存中记录默认值及所属选择器。

后续月份工具只能接管这个已观察的默认值：节点和容器仍相同、值未变化、没有用户真实交互时，才按已确认资料选择月份。原先就有的值、后来被用户修改的值都继续保护。默认值本身不进入日志。

这是一种局部的动作来源追踪。我们没有建立通用的“覆盖已有内容”权限，而是在一个可验证的动作链中区分用户输入和页面副作用。

## 5. 工具参数编译与无候选任务

模型工具使用 JSON Schema 约束输出。有字段而没有合法来源时，如果仍生成空的 `enum` 或 `anyOf`，模型服务商可以在推理前拒绝请求。

因此动态 Schema 也是需要校验的程序产物。无资料候选的区块直接生成 `missing_profile`，其余区块继续规划。模型给出的路径仍需要通过完整快照、事实存在性、日期用途和经历索引校验。

这体现了任务分解中的确定性处理：已知没有资料的情况可以由程序解决，把确实需要语义理解的候选匹配交给模型。

## 6. 诊断边界与证据强度

执行日志记录阶段、工具、路径、候选数量、布尔身份结果及默认值修正标记。模型接口诊断读取限长响应，只输出已知类别、HTTP 状态和契约结构统计，不输出服务商错误原文或请求体。

这种闭合诊断能解释“失败发生在哪”，同时避免把无法控制的字符串复制到执行记录中。

评测也分层：单个控件协议测试、生产执行器的虚构完整流程、真实网页核验。真实界面出现结果后还要检查最终组合是否正确。32 个字段成功回读并不能证明年月都对，月份联动就是这次发现的例子。

## 当前能力与继续方向

本次完成了动态控件状态与局部副作用管理，让观察和回读更接近真实网页行为。它仍是浏览器表单 Agent 的一个执行层能力。

下一步可沿着已确认的失败扩展：在控件菜单证据上选择适配器，给复合日期和级联地区建立更完整的状态转换；增加不同页面布局和组件协议的评测。引入更多框架前，先保证任务状态、工具边界和验收条件能够解释实际成功与失败。
