# 边做边学路线图

每一步都先写出可运行成果和验收条件，再讲清楚它在全系统中的作用。状态表示截至 2026-10-04。

| 阶段 | 要完成的成果 | 要掌握的技术 | 参考与验收 |
| --- | --- | --- | --- |
| 0：旧版留档 | 当前版本压缩包、校验值、恢复说明 | 可恢复快照、数据隔离、来源追踪 | 已完成；108 个文件逐文件校验 |
| 1：Agent 运行内核 | 观察／决策／执行／验证循环，工具白名单，合成环境，轨迹与评测 | ReAct、工具调用、Zod、后置条件、状态机、任务评测 | 已完成；`npm test`、`npm run bench` |
| 2：真正的模型决策 | 接入可替换的 LLM 适配器，让模型根据网页字段和资料目录选择动作 | 结构化输出、函数调用、上下文构造、提示注入防护、成本与超时控制 | 接口测试已完成，真实模型在本地 Chrome 演示页成功；32 案例内存评测已建立基线 |
| 3：Browser Use 浏览器 Agent | 用 Browser Use 的 `Agent`、`BrowserSession`、`Tools` 驱动本地测试页，并独立核对结果 | CDP、DOM 观察、动作注册、模型输出契约、工具反馈 | 本地 Python 试运行已完成：两段虚构教育经历与四字段 4/4；真实网站、复杂控件与网页执行记录接入仍待实现 |
| 3.5：普通 Chrome 工具栏入口 | 在用户现有 Chrome 中点图标选当前标签页；扩展后台复用 Agent 闭环；本机模型服务返回决策 | Manifest V3、`activeTab`、`scripting`、WebSocket、标签页身份校验 | 已在日常 Chrome 安装并点击验证：Agent 添加一张卡片、填写并核验 4/4 个虚构字段；目前只允许本地虚构页 |
| 4：复杂任务与恢复 | 多经历、奖项／竞赛路由、自定义控件、失败重规划、任务中断后恢复 | Browser Use 历史与工具扩展、工作记忆、检查点、幂等性、可靠性工程 | 进行中：本地网络探针、杭州银行只读扫描已验证；0.5 增加资料来源检查、只读模型映射、记录缺口和复扫失效，三个真实模型合成规划样例通过。真实资料导入、复杂控件执行、可靠恢复、延迟副作用与真实网站安全验收仍未完成 |
| 5：系统评测与项目展示 | 多网站匿名任务集、成功率／误填率／耗时／费用／安全指标、可复现报告 | Agent benchmark、消融实验、轨迹分析、失败分类 | 参考 BrowserGym、AgentLab；32 案例合成基线已完成，浏览器与真实网站结果尚缺 |

阶段 2 是“从运行时走向真正的 LLM Agent”的关键一步。阶段 1 的脚本决策器和阶段 2 的模拟 HTTP 响应都不能当作语义理解能力。本地 Chrome 演示页和 Browser Use 对照实验均已用真实模型完成两段虚构教育经历；后者使用 Browser Use 的实际 Agent 循环与受限工具表。32 案例的内存评测给出首轮基线：25/32 通过，复杂控件 0/5，且一个合成按钮暴露了提交副作用漏洞。这组基线属于原 Node 运行路径，尚不能算作 Browser Use 的评测成绩。详见[评测说明](evaluation.md)和[Browser Use 改造说明](browser-use-migration.md)。进入真实网站适配前，需要在普通 Chrome 的虚构测试站点验证选项提交状态和浏览器级提交防护。多 Agent 分工暂不作为必需目标；先通过评测证明单 Agent 的瓶颈，再决定是否引入 Planner/Navigator。

本轮按 [GitHub 调研](../reports/github-resume-agents-2026-10-04.md)补上资料依据和可检查的规划层。建议接下来先接入已有资料库的导入预览与冲突处理，再实现自动补全/下拉的受限工具，然后做多经历增补、持久检查点与网站操作经验，最后扩展多站点评测。LangGraph 的状态与持久化放在恢复阶段实际落地；当前没有新增该依赖。只读规划 3/3 属于小样例，不替代原 32 案例或真实浏览器验收。
