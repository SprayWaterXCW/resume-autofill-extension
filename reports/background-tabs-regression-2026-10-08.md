## 两个可复现的代码问题

### 1. 已受理启动后再次检查活动页

worker 在开始时检查用户选中的活动标签页，随后 `preview` 又在异步页面清理前后检查活动标签页。用户在第一次检查通过后立即切到另一个页面，后一次检查会拒绝已经受理的原页面。

新增回归在生产清理调用处暂停 A 的启动，切到 B，再放行。修复前启动返回失败；修复后 A 继续准备自身页面，B 可同时开始，切到第三页后两页各只写自己的文档。

修复：用户开始时检查活动页；受理后的准备工作检查任务保存的 `tabId` 和精确网址。后续仍使用 `documentId` 执行，刷新同网址不会允许旧动作进入新文档。

### 2. MAIN 输入状态核验重新依赖网页计时器

0.7.28 的 `commitPageInput` 在网页 MAIN 世界等待 160 ms 才返回。此前普通适配器已迁移到扩展后台等待，但新输入提交路径又引入了网页计时器依赖。

新增真实 React 夹具模拟无原生焦点并拒绝网页计时器。修复前生产输入流程报 `PAGE_INPUT_EXECUTION_FAILED`；修复后基本信息、实习和校园多行说明仍可完成输入与状态复核，网页计时器调用为 0。

修复：页面执行一次输入、变更和失焦后立即返回；扩展 service worker 等待 160 ms，再以同一目标标记执行只读核验。核验不会再触发输入或失焦事件，也不会重复写入。组件值丢失、组件状态凭据消失或文档替换仍不能获得成功回执。

夹具证明了对网页计时器的依赖及其修复，不能代表当次用户页面恰好触发了哪一种 Chrome 后台调度状态。

## 诊断改进

`pageDiagnostic` 只接受预定义阶段、触发原因、异常类别和布尔事实。可以区分启动准备失败、加载事件、关闭、网址不匹配、文档不匹配、后台重启以及脚本执行失败；脚本失败时可记录原页是否活动、是否丢弃、是否加载、网址是否仍匹配。

输入错误 `PAGE_INPUT_EXECUTION_FAILED` 通过 runner 保留，不再统一折叠为 `REAL_WRITE_FAILED`。复制记录与本地服务日志保留经过白名单检查的证据；完整网址、浏览器原始错误消息、资料值与 API 密钥不进入诊断。
