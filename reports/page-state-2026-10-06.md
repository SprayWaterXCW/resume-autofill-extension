## 根因证据与修复

通过 Chrome 的只读调试检查实际网页处理函数，观察到两条不同链路：

- 部分输入的变更处理只执行组件自己的 `setState({value: ...})`，其失焦处理才向外层传递 `{value, text}`。
- 多行说明同样在变更时更新内部值，失焦时将当前说明通知外层表单。

因此 DOM 值一致，甚至输入组件当前值一致，都不充分。0.7.27 的中间预览失败直接证明了这一点。

0.7.28 对已绑定的单个控件执行输入与变更，调用原生失焦，并记录 `blur/focusout` 是否发生。缺少哪一个事件才补发哪一个。最终轮 **44 个普通输入／多行文本动作均记录 `syntheticBlurUsed=true`，写入时 `documentFocused=false`**；结束审计保留 44 个输入组件值一致的结果。网站暂存与刷新提供了业务表单实际接收的独立证据。

MAIN 执行仅处理一次性票据关联的输入目标，后台继续绑定原标签页和文档。生产代码不调用 React 回调、不修改 React 跟踪器或业务 store、不发送保存请求。组件属性只作为本地只读证据；日志只返回封闭布尔项。

## 新的填写模式

- 「全部覆盖」为默认值：已有普通内容按资料库更新，缺少来源不清空。
- 「只填空白」：已有值保留，并在真正写入时再次检查用户编辑竞态。
- 每个任务固定启动时的模式；修改偏好只影响后续任务，多个标签页互不改变。
- 写入权限、语义来源、文档绑定、声明／签名／上传等边界继续检查。

真实验收使用默认覆盖。空白模式与偏好保存、快照指纹、写入竞态、两页独立冻结由虚构回归覆盖，没有为真实测试改动配置。
