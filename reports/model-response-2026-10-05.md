# 模型返回格式与规模规划修复 — 2026-10-05

## 真实失败的证据

用户提供的 0.7.3 执行记录：Moka 页面发现 57 个字段、3 个分组，资料目录 201 个路径，其中 33 个派生项。任务第一次模型规划失败，未尝试表单动作，网络恢复记录为 NO_PAGE_ACTIONS。

本机服务在 2026-10-05T14:15:10.770Z 与 14:15:29.977Z 连续记录 PLAN_MODEL_RESPONSE_INVALID，请求分别耗时 5458 与 4583 毫秒。这个代码来自规划返回解析层。旧代码用同一错误覆盖工具调用缺失、工具调用数量不对、参数 JSON 错误和 schema 错误，没有保存解析子原因，无法事后确定原次具体违反了哪项契约。

本轮遵从用户不查看浏览器的要求。只读取本地日志与代码，以虚构资料和 DOM 测试、元数据模型请求验证；未读取或操作真实招聘页面。

## 修复内容

1. 返回解析诊断增加六个阶段：tool_call_missing、tool_call_count、tool_call_invalid、output_truncated、arguments_json、arguments_schema。
2. responseDiagnostic 在服务端、WebSocket 客户端、修复反馈中均按封闭 schema 校验。只保留类型、数量、长度、固定字段路径和 token 指标，排除正文、参数片段、未知属性名、私有值和密钥。
3. 返回格式错误接入既有最多三次的规划修复。每轮错误产生事件，重试前检查完整快照；三次仍无有效计划时停止，未校验提议不能执行。
4. 工具清单删除逐字段重复的完整来源列表，外层来源枚举与分支的实际来源一致；已有内容、禁用和声明等目标不再列入候选。
5. 模型输入改为候选视图：待处理字段、候选来源及递归依据；完整区块计数保留。完整上下文留在程序内，最终计划和卡片缺口按完整资料复验。
6. 可选角色 null 表示未提供；已知普通目标、普通来源上的获奖专用角色注解移除，不改变字段或路径。其他非法角色、额外值、未知引用和语义冲突继续拒绝。
