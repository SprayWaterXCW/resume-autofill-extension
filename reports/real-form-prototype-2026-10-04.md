# 真实表单填写原型：0.6.4

日期：2026-10-04。仅记录机制和计数，不记录用户简历值。

## 已实现

- 导入原插件单份简历 JSON、当前活动模板导出、结构化 profile。
- 私有资料账本与仅包含标签/路径的模型目录。
- LLM 函数调用生成映射；程序校验来源、引用、经历顺序。
- 普通 Chrome 当前标签页执行，真实填写按钮已开放给已导入个人资料的 HTTP(S) 页面。
- 添加经历后重新扫描并重新规划，支持文本、数字、原生日期和下拉、部分自定义下拉和单选。
- 原有内容保留，自动补全未选中时恢复搜索词，失败字段不阻断其他独立字段。
- 每步回读与整页最终复核，停止和复制执行记录。
- 操作期间及结束后保留网络保护，用户核对后手工解除。
- 虚构验收资料用途标记，不能用于外部招聘网站。

## 当前范围

- 远程学校检索可能因网络保护无法取得候选，报告失败并恢复输入。
- 级联地区、复杂日期面板、文件上传、iframe 和 Shadow DOM 内部控件尚未完整适配。
- 没有执行保存草稿、签名、声明勾选、提交简历、投递或注册。
- 真实页面目前使用 LLM 映射与受限批次执行；尚未完成 Browser Use 全套通用动作循环或完整复现。

## 外部网站状态

开始阶段只读观察到京东方招聘登录页，随后用户自行操作到职位列表。当时未操作短信验证码、协议、登录/注册或投递按钮，也尚未向该网站填写资料。用户随后选定的编辑页实测见下文。

### 京东方编辑页的观察与首轮故障

用户随后进入京东方简历编辑表单并指定在这里测试。已有标准简历文件通过原生文件选择器导入扩展本地：142 个资料项；教育、实习、项目各 2 组，校园经历 3 组，证书与语言记录已识别，获奖与竞赛各 5 组。没有把个人资料值加入仓库、报告或模型请求。

首轮观察：59 个字段，58 个标签缺失，所有字段合并在一个分组。读取实际 DOM 后补入 Phoenix 标签、控件及标题结构，并增加父节点查找深度。Chrome 再扫同一页面：8 个字段分组、59 个字段、2 个标签缺失；控件类型为自定义下拉 28、文本 25、多行文本 4、复选 2。

第一次执行在模型计划校验阶段停止，新增与写入均为 0。现有错误码不足以定位，故增加只包含合法引用的诊断，再生成只读计划。服务日志给出：

```json
{"code":"PLAN_DUPLICATE_REFERENCE","diagnostic":{"violation":"section_in_multiple_groups","groupIds":["group-1","group-8"],"sectionKeys":["jobPreferences"]}}
```

据此修复普通资料对象跨网页分组的限制，保留重复经历分配与重复字段/路径的检查，并修正模型请求计数在失败时显示为 0 的问题。当前源代码构建成功，66 项 Node 测试通过。进入下一次实际填写前需要在 Chrome 重新加载已安装的修复版本。

### 网络屏蔽恢复：0.6.2

用户返回京东方职位页后，Chrome 显示“此页面已被某个扩展程序屏蔽”与 `ERR_BLOCKED_BY_CLIENT`。Agent 面板仍显示本标签页网络保护。源码确认其规则阻断 `main_frame`，恢复流程依赖页面注入成功才删除规则；Chrome 错误页无法执行注入。

修复恢复顺序后第一次重新加载扩展，面板不再显示保护，但页面仍被屏蔽。进一步增加实际规则检查，随后面板明确显示“扩展更新后检测到当前标签页仍暂停联网”，确认了面板状态与规则状态不一致。通过新恢复入口解除规则并刷新，实际浏览器出现京东方职位名称、岗位职责和正常页面链接，错误消失。

当前安装版本为 0.6.2，权限没有增加。已通过浏览器历史返回用户原先的简历编辑页，教育、实习、获奖及页面操作区域正常显示。未点击职位申请、暂存或提交。

新增测试覆盖错误页注入失败、导航后恢复、其他规则/标签页不受影响、删除结果核验、纯规划失败自动恢复、已尝试写入继续保护、后台中断保留保护、更新丢失状态后的规则恢复。

### 映射校验反馈：0.6.3

恢复页面后的一次运行在规划阶段收到 `PLAN_RECORD_MISMATCH`，写入与添加均为 0，访问自动恢复。旧日志只有错误码，故为记录顺序和缺失分组声明补充合法引用诊断。随后只读规划成功关联 28／59 个字段，显示 13 组经历缺口，说明输出并非每次都出现相同错误。

再次运行时服务日志定位到：

```json
{"code":"PLAN_RECORD_MISMATCH","diagnostic":{"violation":"field_section_unmapped","groupIds":["group-1"],"fieldIds":["field-27"],"sourcePaths":["jobPreferences.expectedCity"],"sectionKeys":["personal","contactAndLocation","identityAndAuthorization"]}}
```

据此增加最多 3 次规划调用的反馈重试，所有反馈经白名单检查，计划通过校验后才开始动作。测试验证错误记录被修正后才写入、页面变化会停止重试、未知记录或私有文本不能进入反馈、连续失败不留只读网络屏蔽。75 项 Node 测试通过，扩展构建成功。Chrome 管理页已实际确认重新加载为 0.6.3，权限没有增加。

### 计划规范化：0.6.4

0.6.3 的实测执行记录确认三次模型调用和两次反馈重试，但第三次仍收到缺失分组声明错误，写入与添加为 0，网络自动恢复。日志还记录 `languages.0.name` 关联个人信息字段却漏写 `languages` 声明。

0.6.4 从合法字段引用中的资料 sectionKey 补齐声明，再执行原有记录池与重复引用检查。新增回归验证省略分组声明可以补齐，而错误记录索引与未知路径仍被拒绝。76 项 Node 测试通过，扩展构建成功；Chrome 管理页已确认 0.6.4，权限没有增加。
